LKAS

차량용 전방카메라 기반 객체 인식 알고리즘 개발

ADASComputer VisionTSRVehicle DetectionDSP PortingFailsafe

차량 전방 카메라를 기반으로 차선 유지 보조 및 운전자 지원 기능을 제공하는 ADAS 개발 프로젝트에서 TSR 표지판 인식, VD 선행차량 인식, Failsafe 로직, 양산 환경 적용을 위한 최적화 작업을 수행하였다.

TSR 알고리즘은 독일 Fraunhofer 연구소와 공동으로 수행한 국책과제를 통해 개발되었다. 이 과정에서 요구사항 정의, 기능 분해, 검증 항목 관리, 테스트 결과 피드백까지 이어지는 독일식 시스템 엔지니어링 프로세스를 경험하였다. 반면 VD 알고리즘은 만도 내부에서 처음부터 자체 개발한 알고리즘으로, 초기 단계에는 학습 데이터셋부터 새로 구축해야 했다.

한국, 인도, 독일 등 다양한 실제 도로 환경에서 수집된 수만 시간 규모의 카메라 로그를 기반으로 객체 Annotation, 데이터 정제, 품질 검증, 클래스 분류, Hard Negative Mining, 전처리 파이프라인을 구성하였다. 모델 개발은 한 번의 학습으로 끝나는 구조가 아니라 데이터 수집 → Annotation → 전처리 → 학습 → 평가 → 오류 분석 → 데이터 보강 → 재학습으로 이어지는 반복 루프를 통해 성능을 점진적으로 개선하는 방식으로 진행되었다.

Data Logging→Annotation→Preprocessing→Training→Evaluation→Error Analysis→Retraining

실도로 환경에서의 문제 해결

실제 주행 영상은 통제된 데이터셋과 달랐다. 국가별 표지판 디자인 차이, 주야간 조도 변화, 터널 진출입, 역광, 비·눈·안개, 렌즈 플레어, 모션 블러, 차체 진동, 카메라 장착 위치 변경, 렌즈 설계 변경에 따른 영상 왜곡이 인식 성능에 직접 영향을 주었다. 또한 부분적으로 가려지거나 훼손된 객체, 원거리 저해상도 객체, 강한 그림자 영역에서는 오탐지와 미탐지가 동시에 발생하였다.

이 문제를 해결하기 위해 데이터 증강, 전처리, Hard Negative 보강, 오류 케이스 재수집, 평가셋 재구성, threshold 튜닝을 반복하였다. 단순히 전체 정확도만 보는 것이 아니라 실제 차량 기능 관점에서 위험한 미탐지와 사용자 경험을 해치는 오탐지를 분리하여 분석하고 개선하였다.

양산 환경 적용과 임베디드 최적화

차량용 DSP 프로세서는 서버급 연산 자원을 사용할 수 없기 때문에 모델의 정확도만큼 Latency와 메모리 사용량이 중요했다. 모델 개발 이후에는 DSP 포팅을 위해 모델 크기 축소, 파라미터 최적화, Fixed Point 변환, 연산량 감소, 메모리 배치 최적화 작업을 수행하였다. 모델을 줄이면 실시간성은 좋아지지만 인식 성능이 떨어지고, 정확도를 높이면 처리 시간이 증가하는 구조였기 때문에 다양한 네트워크 구조와 파라미터 조합을 실험하며 정확도와 Latency 사이의 균형점을 찾아야 했다.

이 프로젝트를 통해 데이터 엔지니어링, 컴퓨터 비전, 머신러닝 모델 개발, 임베디드 최적화, Failsafe 설계, 양산 검증 프로세스까지 제품 개발 라이프사이클 전반을 경험하였다. 해당 기술은 이후 현대·기아차 다수 차종에 적용되어 실제 도로 환경에서 운전자 지원 기능으로 활용되었다.

TankBattle.JS

JavaScript 기반 AI 코딩 교육 플랫폼

Vanilla JSP5.jsNode.jsFirebaseGeneratorYield Injection

TankBattle.JS는 블록 코딩에서 텍스트 코딩으로 전환하는 과정의 학습 장벽을 낮추기 위해 설계한 게임형 코딩 교육 플랫폼이다. 학습자는 JavaScript로 탱크 AI를 작성하고, 그 코드가 실시간 전투 결과로 반영되는 과정을 통해 프로그래밍 개념을 체득한다.

프로젝트의 핵심 목표는 단순한 문법 학습이 아니라 알고리즘적 사고와 문제 해결 능력을 학습자가 직접 경험하게 만드는 것이었다. 이동, 탐색, 공격, 회피와 같은 게임 내 행동은 함수, 조건문, 반복문, 상태 관리, 디버깅 개념과 자연스럽게 연결된다. 학습자는 코드 한 줄의 변화가 전투 결과에 어떤 영향을 주는지 시각적으로 확인하며 추상적인 문법을 실제 문제 해결 도구로 받아들이게 된다.

Yield Injection: 단일 스레드 위의 협력적 멀티태스킹

가장 큰 기술적 과제는 여러 탱크 AI가 동시에 동작하는 환경을 JavaScript의 단일 스레드 구조 위에서 구현하는 것이었다. 각 탱크는 이동, 회전, 발사처럼 시간이 소요되는 행동을 수행해야 하지만, 학습자에게 async/await나 Generator 같은 고급 비동기 문법을 요구하면 교육 목적이 무너진다.

이를 해결하기 위해 런타임 단계에서 사용자 코드를 분석하고 moveForward, turnRight, fire와 같이 시간이 걸리는 명령 앞에 자동으로 yield를 삽입하는 Yield Injection 방식을 설계하였다. 학습자는 순차적인 코드만 작성하지만, 내부적으로는 Generator 기반 협력적 스케줄링 구조로 실행되어 60fps 게임 루프 안에서 여러 AI가 동시에 동작하는 효과를 만든다.

Command Pattern 기반 게임 엔진

게임 엔진은 이동, 회전, 발사, 재장전 등 모든 행동을 독립된 Command 객체로 추상화하였다. 매 프레임마다 현재 Command가 일정량 실행되고, 완료되면 다음 Command로 전환된다. 이 구조 덕분에 지형 타입에 따른 속도 감쇠, 탄약 타입별 재장전 시간, 시각 효과, 파티클, 스크린 셰이크, 플로팅 텍스트 등을 동일한 루프 안에서 통합적으로 다룰 수 있었다. 새로운 행동 타입이나 맵 오브젝트를 추가할 때도 기존 엔진 로직을 크게 변경하지 않고 Command 클래스를 확장하는 방식으로 대응할 수 있었다.

안전한 사용자 코드 실행 환경

사용자가 직접 작성한 JavaScript 코드를 실행해야 했기 때문에 안정성과 보안이 중요한 설계 요소였다. 무한 루프, 런타임 오류, 전역 객체 오염, CPU 독점 문제를 막기 위해 Loop Protection, try-catch 래핑, API 격리, 프레임당 Generator 진행 횟수 제한을 적용하였다. 잘못된 코드가 제출되더라도 전체 서비스가 멈추지 않고 해당 탱크만 안전하게 퇴장하도록 설계하였다.

위험 요소대응 방식
무한 루프빈 루프 감지 및 wait 삽입, 실행 흐름 양보
런타임 오류try-catch 래핑, 연속 오류 발생 시 해당 탱크 자동 퇴장
전역 객체 오염탱크 API를 별도 World 객체로 격리
CPU 독점프레임당 Generator 진행 횟수 상한 적용

교육 플랫폼으로서의 확장성을 위해 배틀 엔진과 튜토리얼 엔진은 분리하였다. 실시간 대전, 물리 시뮬레이션, 승리 조건 판정은 배틀 엔진이 담당하고, 32개 미션 커리큘럼, 문법 검증, 동작 결과 검증, 힌트 UI, 학습 진도 추적은 튜토리얼 엔진이 담당한다. 이를 통해 교육 콘텐츠를 수정해도 배틀 기능의 안정성에 영향을 주지 않는 구조를 확보하였다.

튜토리얼은 JavaScript 기초, p5.js Creative Coding, TankBattle 전략 설계로 구성되었으며, 코드 문법 검증과 물리적 동작 결과 검증을 동시에 수행한다. 틀린 코드가 우연히 성공 조건을 통과하는 것을 막는 동시에, 비표준적 풀이더라도 결과가 올바르면 인정하는 유연한 평가 체계를 적용하였다.

PolyTrader

Genetic Programming 기반 예측시장 전략 생성·검증 시스템

PolymarketGenetic ProgrammingBacktestingTypeScriptRisk ManagementStrategy Evolution

PolyTrader는 생명의 진화 원리에서 모티브를 얻어 변화하는 시장 환경에서도 살아남을 수 있는 거래전략을 자동 생성·검증하는 핀테크 자동매매 시스템이다.

시스템은 글로벌 예측시장인 Polymarket에서 BTC, ETH, SOL, XRP 등의 단기 시장 데이터를 수집하고, Binance 가격 데이터와 Polymarket의 호가·체결 데이터를 결합해 전략 학습용 시계열 데이터로 전처리한다. 핵심 아이디어는 거래전략을 하나의 DNA 개체처럼 다루는 것이다. 각각의 전략은 고정 규칙이 아니라 가격 조건, 시간 조건, RSI, Bollinger Band, 변동성, gap momentum 등 여러 신호 블록이 결합된 트리 형태의 수식 구조로 표현된다.

예를 들어 특정 토큰 가격이 일정 구간 이하이고, RSI가 과매도 상태이며, 세션 초반에만 진입한다는 조건은 하나의 전략 DNA가 된다. 시스템은 이러한 전략 DNA를 수천~수만 개 생성해 population을 구성하고, 과거 시장 데이터에 대해 백테스트를 수행한다.

전략 진화 파이프라인

각 전략은 기대수익(EV), 승률, Sharpe ratio, profit factor, 최대 낙폭, 거래 빈도 등의 평가함수로 점수를 받는다. 성과가 낮은 전략은 제거되고, 상위 전략은 다음 세대의 부모 개체로 선택된다. 이후 조건 일부를 교체하거나 파라미터를 변형하거나 서로 다른 전략 블록을 재조합해 자손 전략을 생성한다. 이 과정을 여러 세대 반복하면서 시장 데이터에 더 잘 적응하는 전략 후보를 탐색한다.

Market Data→Signal Blocks→Strategy DNA→Population→Backtest→Selection→Mutation / Crossover

단순히 과거 수익률이 높은 전략을 찾는 데 그치지 않고, 수수료, 스프레드, 주문 체결 방식, latency, 미체결 주문, 리스크 제한을 함께 반영하였다. 또한 학습 데이터와 검증 데이터를 분리해 과최적화된 전략을 걸러내고, 실제 운용 가능한 전략만 TypeScript 코드와 JSON 설정으로 자동 변환해 실시간 자동거래 런타임에 연결할 수 있도록 설계하였다.

이 프로젝트는 사람이 직접 아이디어를 전략으로 코딩하는 방식을 넘어, 시장 데이터를 기반으로 전략 후보를 대량 생성하고, 생존 경쟁을 통해 우수한 전략을 선별하며, 검증된 전략을 자동거래 시스템에 배포하는 end-to-end 전략 진화 플랫폼이다. 금융공학적으로는 예측시장 가격을 확률 기반 파생상품 가격으로 해석하고, 시장의 비효율이 수수료와 실행 지연 이후에도 기대값을 갖는지 검증한 사례이며, 기술적으로는 데이터 수집, 전처리, genetic programming, 백테스트, 최적화, 리스크 관리, 자동매매를 하나의 파이프라인으로 통합한 프로젝트이다.

JCHAT

숙박업 운영자동화 AI 챗봇 서비스

LLMNode.jsMulti-TenantKnowledge SnapshotPrompt CacheSaaS

JCHAT은 숙박업소 운영자가 숙소 정보를 직접 관리하고, 투숙객은 객실 QR 또는 링크로 접속해 AI 챗봇에게 즉시 질문할 수 있는 숙박업 운영 자동화 서비스이다.

핵심은 단순 FAQ 챗봇이 아니라 숙소마다 운영자가 승인해 발행한 최신 지식 스냅샷만 답변에 사용하도록 설계했다는 점이다. 체크인, 주차, 와이파이, 객실 사용법, 부대시설, 안전 규정, 객실별 추가 정보 등을 구조적으로 나누어 관리하고, 실제 투숙객에게는 해당 숙소의 최신 정보만 안정적으로 전달되도록 구성하였다.

멀티테넌트 운영 구조

기술적으로는 Node.js 기반 백엔드 위에 멀티테넌트 구조를 구현하고, 플랫폼 관리자, 숙소 관리자, 투숙객 모바일 챗봇이라는 세 가지 관점을 분리하였다. 플랫폼 관리자는 전체 업체 상태, 가입과 결제 흐름, 운영 이슈, LLM 사용량을 확인한다. 숙소 관리자는 자기 숙소의 지식베이스, 객실 정보, 알림 설정, 스냅샷 발행을 직접 관리한다. 투숙객은 모바일에 최적화된 챗 UI에서 빠르게 답변을 받는다.

이 구조는 하나의 AI 기능을 세 사용자층의 서로 다른 목적에 맞게 분리된 UX와 운영 지표로 풀어낸 사례이다. 단일 챗봇 기능을 만드는 것이 아니라 실제 운영자가 지속적으로 정보를 관리하고, 플랫폼 관리자가 비용과 사용량을 관찰하며, 투숙객이 오류 없이 정보를 얻을 수 있는 운영 가능한 제품 구조를 목표로 하였다.

LLM 비용 최적화와 사용량 추적

LLM 연동은 답변 품질과 비용을 함께 고려해 설계하였다. 같은 숙소의 요청은 최대한 동일한 정적 프롬프트 구성을 재사용하도록 prompt_cache_key를 숙소 단위로 고정하고, 지식 스냅샷을 캐시 친화적인 구조로 프롬프트 앞단에 배치하여 캐시 히트를 유도하였다. 반복 질문이 많은 숙박업 특성에 맞춰 API 비용을 크게 줄일 수 있는 구조를 목표로 하였다.

동시에 각 요청마다 입력 토큰, 출력 토큰, 총 사용량을 기록하여 어떤 업체가 얼마나 비용을 사용하는지, 어떤 질문 유형이 비용을 많이 발생시키는지 추적할 수 있도록 설계하였다. 이는 LLM 기반 SaaS에서 기능 구현만큼 중요한 운영 안정성과 원가 관리의 기반이 된다.

데이터 입력 자동화

또 다른 핵심 기능은 데이터 입력 자동화이다. 숙소 운영자가 이미 보유한 규칙 문서, 홈페이지 안내문, 운영 메모, 이미지 형태의 규칙표를 AI가 분석하여 현재 지식베이스 항목에 맞게 자동 매핑하고 초안을 제안하도록 설계하였다. 운영자가 모든 정보를 새로 입력하는 것이 아니라, 기존에 축적된 자료를 AI로 해석해 구조화된 데이터로 임포트하는 흐름이다.

이 접근은 현업 사용성을 크게 높이는 요소였다. 숙박업소마다 운영 규칙과 객실 정보가 다르고, 정보 변경도 잦기 때문에 단순 FAQ 등록 방식으로는 지속 운영이 어렵다. JCHAT은 운영자가 정보를 승인하고 스냅샷으로 발행하는 구조를 통해 답변 신뢰성과 관리 편의성을 함께 확보하였다.
